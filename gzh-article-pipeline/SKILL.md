# 微信公众号全流程创作与发布流水线 (GZH Article Pipeline)

本流水线采用模块化渐进式调度架构，实现从选题策划、视觉生成、人性化写作、高质感排版到官方草稿箱直推的全闭环自动化。

---

## 双轨触发机制 (Dual Entry Trigger)

* **【模式 A：自主选题与今日规划模式】**
  * **触发时机**：用户未给具体链接，提出“今天选个题”、“给几个选题”、“按爆款准则选题”、“今天写什么好”；
  * **执行动作**：执行 **【阶段零：爆款选品准则与高转化选题引擎】**，输出 3 个符合 S/A 级公约数的候选方案。
* **【模式 B：指定链接/项目直接写作模式】**
  * **触发时机**：用户直接提供 GitHub 仓库、官网、文章链接或素材（如：“写一篇关于 BCUninstaller 的文章”）；
  * **执行动作**：直接从 **【阶段一：阅读输入与视觉锚点规划】** 启动，顺次执行完整流水线。

## 核心工作流 (标准化执行阶段)

### 阶段零：爆款选品准则与高转化选题引擎 (模式 A 专用)
> 🚨 **渐进加载指令**：执行本阶段前，必须调用 `view_file` 查阅 `references/topic_selection.md`（包含 GhostTrack 2万读、GhostDownloader 7.2千读实战模型、六道立项生死门、平台版权防火墙与**【死刑复核机制】**）。
> 🛰️ **实证数据雷达与推荐流生存预测 (Empirical Viability Gatekeeper)**：优先读取 `references/account_empirical_profile.json`（由数据诊断工具自动生成）。
> - **若文件存在**：提取本号常读私域基准线（如 105~157 阅）、近期爆款冠军（如《旧iPad别扔》4,082阅/85.9%推荐）、以及近期熔断题材黑名单（如百度网盘加速/小号反查等零推荐案例）。对当前候选选题进行**【公域算法生存率预测】**，凡命中近期熔断模式（如专业度过高/公域CTR低）的选题，必须强制要求标题降维泛化或一票否决！
> - **若文件不存在**：优雅降级（Graceful Fallback），直接遵循 `references/topic_selection.md` 静态规则执行，流程绝不中断。
1. **死刑复核穿透审查（最高生死前置）**：任何候选标的必须通过【动态存活性死刑复核】（检查仓库源码是否清空、近6个月是否有有效Commit、Issue是否满屏失效暴雷、当前最新系统/宿主版本是否真实兼容）。严禁迷信历史Star数，空壳仓/失效仓直接判死刑一票否决；
2. **象限与高价值 eCPM 赛道约束**：首要通过 **门禁 0（商业防火墙与版权自杀门）**，严禁触碰腾讯 TME 周杰伦/QQ音乐VIP、腾讯视频VIP及微信生态外挂；在满足大众痛点与零门槛前提下，**强制优先挑选高 eCPM 垂直赛道开源标的**——优先对齐实证高单价池（**办公表格/文档生产力 `¥8.85~¥27.08`、金融/宏观盯盘/比价消费 `¥8.66~¥21.55`、教育/知识图谱 `¥15.76+`、汽车养护/私人云存储硬件 `¥4.37~¥11.43`**），**非重大现象级爆点，尽量避开纯通用下载器/浏览器插件/系统卸载清理等低单价工具（实测 `eCPM` 仅 `¥1.37~¥2.25`）**；依次通过基数门、炸药门、开箱门、奇迹门、社交门，一票否决第 IV 象限自嗨题材；
3. **千次转发社交货币审查**：确保预期分享率 > 10%（冲刺 1,000 次群聊转发阈值），明确具体的群聊转发第一句话；
4. **四维差异化定位卡扣（防小众自嗨）**：立项具体开源工具前，按 `references/topic_selection.md` 第八节拆解**输入差异 / 流程差异 / 输出差异 / 定位差异**，严格核对是否命中本号 35～60 岁职场居家实用大众基本盘（非小众创作者/纯技术圈层自嗨）；
5. **输出标准化交付物**：汇报 3 个候选选题，包含象限评级、**eCPM 赛道评级与匹配广告主标签**、死刑复核验证状态（含最后更新时间与可用性证明）、四维差异化定位、受害痛点、奇迹时刻、3 套黄金母版备选标题与转发动机。

### 阶段一：阅读输入与视觉锚点规划 (Planning & Shot List)
> 🛰️ **实证数据雷达介入**：若存在 `references/account_empirical_profile.json`，在规划标题时，必须对照近期 TOP 5 爆款高频暴击词库（如“旧iPad别扔/秒变副屏/连根拔起”）与熔断案例，强制确保标题具备公域穿透力。
1. **解析输入**：通过 `read_url_content` 或本地文件读取目标素材；
2. **受众画像与「双高 CTR + 高 eCPM」标题铁律（严格 <= 26 字符）**：校准 36~60 岁高知职场与家庭刚需画像，标题严格 <= 26 字（防微信列表折叠）；**坚持「外层零黑话省钱痛点 × 内层高 eCPM 商业锚点词」**：
   - 🚨 **公域初筛 CTR 闸门与黑话一票否决制**：微信推荐算法第一道死刑门是发文后 0~30 分钟冷启动曝光。如果路人点击率低（CTR < 6%），算法当场物理熔断！
     * **黑话与低价引流双黑名单**：① **绝对严禁** `MD / Markdown / Agent / 智能体 / 紫微斗数 / DNS / 软路由 / 抓包 / 逆向 / 编译 / Docker` 等极客术语；② **门脸尽量去掉** `GitHub / 开源 / X万星 / KDBX` 等技术标签，也**不要写** `白嫖 / 破解` 等把流量打入低价买量广告池的词；
     * **高 eCPM × 泛刚需交集表达**：用普通人秒懂的痛点动作（`别再充会员 / 放网上太危险 / 贴个链接进电脑 / 语音秒变`）绑定高出价商业词（`银行 / 证券 / 合同 / PDF / 会议纪要 / 网课`）；
     * **标题四维百分制门槛（< 75 分禁推）**：按「人群与高值场景匹配 15 + 点击诱因 35 + 结构合规 15 + 爆文潜质 35」打分（`references/writing_playbook.md` 二·0.5 节），仅 S(90+)/A(75-89) 级允许入稿，B/C 级打回重写。
3. **输出 Shot List 表格**：输出标准配图矩阵表格（含 16:9 居中 2.35:1 安全视窗封面及正文插图）；
4. **强制停顿确认**：等待用户明确确认配图方案后，方可进入下一阶段。

### 阶段二：深度人性化写作 (Humanized Writing)
> 🚨 **渐进加载指令**：执行本阶段前，必须调用 `view_file` 查阅 `references/writing_playbook.md` 与 `references/topic_selection.md`（三道递进闸门定律）。
1. **严格篇幅字数铁律（1000 ~ 1300 字精炼流）与防“收藏吃灰中途跳出”熔断机制**：
   - 🚨 **完读率生死线**：纯正文字数**必须严格控制在 1000 ~ 1300 汉字（约 75 秒精读）**，绝对严禁超过 1500 字！
   - ⚠️ **“收藏吃灰”陷阱反侦察**：近期实测数据显示，很多极客文章读者惊叹“太牛了”，随手点【收藏/转发】打算周末再搞，读了 30 秒中途跳出！后台记录完读率仅 15%，冷血算法模型会直接误判为“长而枯燥的低质长文”，彻底掐断公域推流！
   - 💡 **解决方案**：压缩白水，严控字数，不给读者中途跳出的逃逸借口，一口气读完，把完读率死保在 40%+ 通过第 2 关；
2. **消灭 AI 腔调与反“功能说明书”铁律**：老妪能解原则，采用生活化比喻；**每说一个功能点，必须紧跟一句「对你来说意味着什么」的真实收益**，刻薄指向“烂工具/恶心现状”、共情指向读者；全面扫除 `赋能/抓手/打法/闭环/颗粒度/底层逻辑/综上所述/总而言之` 等八股黑话，同时坚持内刊克制，**严禁每段堆砌 Emoji 与文末 `#标签` 串**；
3. **高完读「悬念钩子 + 递进拆短」微节奏工程（2026-11-19 实证校准定稿）**：
   - **开头抓痛点留悬念 · 严禁一上来交底（保 45%+ 完读核心）**：前 3 句只讲透「恶心痛点现场 + 能白拿的爽结果 + 一个实操悬念钩子（如哪两个山寨站千万别点/正确通道在哪）」，**绝对严禁在前 200 字直接抖出工具英文真名、GitHub 地址或全部方法**（避免读者前 40 秒“收藏转发就关页面”把完读率拉垮到 22%）；把真名与关键避坑/上手路径递进放到中后段揭晓；
   - **一段只讲一个意思（手机端严格 2～3 行）**：单段纯文本控制在 35～55 字以内，长句强制拆短，核心结论加粗并独立成段，段与段之间留足呼吸空行；
   - **每屏留一个收获（300～500 字节奏点）**：每 300～500 字置入一个具体案例、操作步骤、对照表（`comparison_table`）或划线金句（`editors_note` / `quote_card`）；
   - **高频轻视觉插图（每 ~300 字一张图）**：每隔约 300 字配一张相关图片，优先采用直白清晰的**实机操作截图 + 简洁常规图文**（比堆砌复杂信息图更快产出，且同样有效打破阅读疲劳）；
   - **标题与正文严格对齐**：标题承诺的方法、清单或结果，在正文中 100% 兑现不跑题，把最终答案与正版地址稳稳落在文末传送门前；
   - **结尾收得轻**：文末用 1～2 句话干脆总结收尾，配合一个小行动引导（如“收藏备用/打开一试”）或极轻互动即可，不写沉重说教。
   - **120 字痛点摘要**：严格限制 80~120 字，遵循“结论价值+痛点后果+免费手段”公式；
4. **执行清单自查**：确保开头不提前剧透答案与网址、标题对齐、每段 <= 3 行、每 300 字有配图或收获点、结尾轻快。

### 阶段三：视觉生成与公众号内联排版 (Generation & Formatting)
> 🚨 **渐进加载指令**：生图与封面设计查阅 `references/visual_system.md`；广告心流埋点查阅 `references/traffic_monetization.md`。
1. **视觉生成双引擎与零延迟自动降级（严禁等待用户提醒）**：
   - 默认优先尝试 API 生图或调用统一调度器 `scripts/generate_image_unified.py`；
   - 🚨 **429 额度耗尽自动容灾铁律**：一旦遇到 429 `RESOURCE_EXHAUSTED` 或配额报错，**严禁中断流程、严禁向用户报错等待提示**！必须**在后台立刻无缝自动调用** `python3 scripts/gemini_web_bridge.py --prompt "..." --output "..."`，直接复用 Chrome 中用户已登录的 Gemini Web Pro (Google One AI Premium) 会话自动打词并截获高清原图，实现完全无人值守的全流程自动保底！
2. **结合文章剧情·满版无留白 21:9 实景封面标准（2026-11-24 最终定稿）**：
   - **拒绝同质化大头模板**：严禁每篇套用同一个“左两行字 + 右墨镜大头”构图！必须依据正文真实剧情定制专属对比实景（如 *拔掉网线本地切发票*、*浏览器泄密 vs U盘双钥匙金库*、*长视频进度条海洋 vs 跟拍卡片*、*吵闹录音笔 vs 点哪句听哪句会议台*），兼顾暴漫火柴人张力与软件真实交互；
   - **文案去极客化 + 高 `eCPM` 锚点**：封面标题与色带严禁写 `GitHub / 开源 / 万星 / KDBX`，只放普通人痛点与金钱/安全/职场收益；
   - **原生 `21:9` 满版直出（零左右留白）**：优先调用 `gemini_web_bridge.py` 直出原生 `21:9`（`1024×434`）edge-to-edge 满版图（元素铺满左右边缘，禁止左右拼接纯色边条或留白边框），推送时加 `--no-safe-crop` 保留满版视觉；正文配图结合实机截图与清爽浅底插图。
3. **内联 HTML 组装**：调用 `references/olive_journal_template.py`（橄榄手记），文末固定保留开源传送门（`github_portal_card`）、底部引导块（`outro_follow_card`）及 **「奇点造物所」微信官方互动账号名片（`mp_profile_card()` / `<mp-common-profile>`）**；推送脚本 `upload_to_wechat.py` 亦会在上传前自动检测并在文末兜底插入该公众号名片（幂等不重复）。🚨 **严禁在正文顶部添加 header_meta 或任何重复标题/作者元信息块**（微信自带官方置顶大标题），**严禁在文末（尤其是 `github_portal_card` 与 `outro_follow_card` 之间）添加任何评论区引导提问段落（如“平时你遇到过吗/欢迎在评论区聊聊你的经历”）、连载预告（SERIES PREVIEW）、留言区互动话题（`interactive_cta_card`）或一键复制微信群安利词（FORWARDING TEMPLATE）**；
4. **格式与 9 项质量机器合规校验**：运行 `LeafWrapper` 与 `LeafValidator` 确保 100% `<span leaf="">` 包裹，且必须执行 `python3 scripts/validate_article.py --input "<HTML路径>" --title "<标题>"`（常规精简流默认 `--profile standard`，若用户明确要求详尽深度图解可传 `--profile deep` 放宽至 `1000~2200` 字）后方可推送草稿箱；封面图须对照 `references/visual_system.md` 五节完成 7 维出图终检。

### 阶段四：一键推送微信公众号草稿箱与定时门禁调度 (Publishing & Timing Gate)
排版与图片准备就绪后，直接运行发布脚本（均位于本 Skill 目录下的 `scripts/`），并执行**发文时段门禁调度器**：

```bash
# 模式 A：首次推送到草稿箱（新建草稿）
python3 scripts/upload_to_wechat.py \
  --html "<排版好的HTML绝对路径>" \
  --images-dir "<图片所在目录>" \
  --title "<文章标题（严格<=26字）>" \
  --author "奇点造物所" \
  --digest "<80~120字以内的四要素痛点摘要>" \
  --cover "<封面图绝对路径>"

# 模式 B：覆盖更新已有草稿（防劣化覆写模式，修改标题/摘要/封面时专用）
python3 scripts/upload_to_wechat.py \
  --html "<本地重新编译的完整HTML路径>" \
  --images-dir "<图片所在目录>" \
  --title "<更新后的标题（严格<=26字）>" \
  --author "奇点造物所" \
  --digest "<更新后的摘要>" \
  --update-draft "<已有草稿的 media_id>" \
  --cover "<新封面路径（若封面未改可使用 --reuse-thumb <已有thumb_id>）>"

# 模式 C：小绿书 / 贴图帖专属推送（article_type="newspic"，含<=20字强校验、中心安全区封壳与实测thumb_url裁切验证）
python3 scripts/upload_newspic.py \
  --images "<首图.jpg>" "<图2.jpg>" "<图3.jpg>" \
  --title "<贴图标题（严格<=20字）>" \
  --content-file "<300~500字精炼贴图正文.txt>" \
  --verify-out "<导出线上203x270实测卡片预览路径.jpg>"
```

#### 🚨 黄金发文窗口调度原则 (Timing Gate Rules)
推送草稿箱完成后，必须显式在回复中提示用户建议的定时群发时间与推荐文案：
* 👑 **【首选发射窗：07:00 ~ 07:20】**：历史平均阅读 **2,250.9**，享有 16 小时完整白天发酵期，冲锋型核武器必须在此窗口发出！
* 🚫 **【每日单发与 72h 防撞车铁律】**：严禁同一天多次群发（`mass=True`）或发重帖试水，每日严格只推 **1 篇 `07:00` 主推**；连续 72 小时内避免连发同一细分题材（如连续两天“手机连电脑/游戏”）或连续 3 篇套用“别再买……”句式，防止常读粉丝脱敏！
* 🌙 **【备选发射窗：20:45 ~ 21:15】**：晚间休闲娱乐档，视听、轻量神器的备选窗口。
* 🛑 **【绝对死亡禁区：09:30 ~ 11:30 早会黑洞】**：历史 60 篇平均阅读仅 140~280，职场早会与清邮件高压黑洞，读者点开两眼即被迫锁屏切掉后台，完读率与即时互动瞬间被腰斩，严禁在此窗口群发主力文章！
* 📅 **【周内节奏战术】**：周五/周六早晨为核武器爆发日；周一全网高压（历史均阅 69.4），严禁排冲锋大题材。

#### 🔄 闭环反馈与 Obsidian 自动归档联动 (Feedback & Archive Loop)
