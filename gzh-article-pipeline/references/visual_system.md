## 一、 生图双引擎调用准则与 429 容灾兜底铁律

1. **第一梯队（默认优先）**：
   - 直接调用 Native Tool `generate_image`（传参 `AspectRatio: "16:9"`），极速生成高精原图；
2. **第二梯队（当触发 429 频率超限、额度耗尽或生图报错时）**：
   - 🚨 **绝对禁止违规降级**：严禁自行降级使用 Python PIL 代码绘制僵硬的表格、方框或文字框当配图/封面！严禁放弃生图或使用空白占位符！
   - 🚀 **强制切换浏览器原生生图**：必须立即自动调用 `scripts/gemini_web_bridge.py` 中的 `generate_image_via_gemini_web(prompt, output_file_path)`；
   - **运行机制**：该桥接脚本通过 macOS 原生 AppleScript 操控 Google Chrome 中已登录的 Gemini 网页端会话，自动注入 Prompt、等待渲染并从 Canvas 捕获无损原图，100% 绕开 API 的 429 配额限制，保证封面与插图永远是高品质手绘艺术图。

## 三、 彩色精修暴走漫画火柴人视觉规范（2026-11-12 最新定稿标准 · 封面与正文通用）

> 🚨 **核心美学铁律**：彻底告别“单薄简陋白纸细线火柴人 + 悬浮 ❌/✅ 圆圈 + 多色俗气金丝带五层堆砌”，封面与后续所有正文火柴人插图统一升级为**「彩色精修暴走漫画火柴人（Rage Comic Stick-Figure Editorial）」**。

### 1. 角色造型与质感铁律（必须纯正火柴人，绝不画成写实人类）
* **头部与身形红线**：主角**必须是光滑纯白圆球脑袋 + 细长管状四肢的火柴人**（🚨 严禁给火柴人画真人头发、耳朵、写实肤色鼻梁或宽大肌肉肩膀！）。
* **表情包灵魂（暴走漫画风）**：五官采用极度夸张搞笑的中国暴走漫画（Rage Comic）经典表情：
  * **左侧痛点人物**：瞳孔地震、张嘴喷泪哭喊、脑门冒青筋/冒烟、满头大汗、头晕蚊香眼；
  * **右侧破局人物**：戴酷黑墨镜、露出经典“姚明嘲讽狂笑 / 狂喜爽笑”表情，跷二郎腿端冰美式或悠闲操作。
* **逼真上色与材质**：告别死板纯白纸片！火柴人身体采用**漫画网点 + 立体明暗阴影**体现体积感；手中道具（发红告警的手机、Windows 桌面大屏、Switch 游戏画面、散落发票/文件堆、书卷、咖啡杯等）必须**高饱和写实上色、带光晕反光与环境氛围质感**。

### 2. 封面「结合正文剧情·满版无留白 21:9 故事流」构图铁律（2026-11-24 最新升级定稿）
* 🚨 **彻底废除“千篇一律左两行大字 + 右墨镜大头火柴人”同质化模板，也严禁在 `16:9` 图左右拼接空白色条导致卡片两边留白过多**：每篇封面必须深入读取文章正文里的**具体动作、物理冲突、软件交互或使用现场**，设计**独一无二的故事对比场景**，让读者 0.3 秒看懂文章在讲什么具体故事：
  * **严禁模板化套娃**：禁止连续使用同一构图公式！必须结合文章真实剧情定制场景骨架——如：
    * *安全加密类*：`浏览器明文泄密破窗 vs 物理U盘双钥匙银行金库门`（体现文章“不传云端+硬件双钥匙”剧情）；
    * *离线文档/合同类*：`云端VIP付费触手抓合同 ❌ ➔ 手拔网线 ⚡️ ➔ 本地浏览器直接印出发票拼A4/电子盖章`（体现文章“拔掉网线照样运行”实景）；
    * *长视频提炼类*：`02:18:45 进度条胶片海洋埋人 vs 电脑自动追踪说话人并剪出3张竖屏金句卡片`；
    * *会议录音转写类*：`吵闹会议现场+天价VIP录音笔 vs 笔记本拆分说话人A/B点击一句秒回听`。
  * **文案去极客化与高 `eCPM` 锚点**：封面主标与副色带**严禁出现 `GitHub / 开源 / X万星 / KDBX` 等技术词**，全部使用大众省钱/安全/职场利益痛点；主标题与副色带自然融入丰富实景构图的上方或左侧清晰处，避免孤立空洞。
  * **满版无空边与色彩区隔**：每篇独立切换配色氛围与场景光源，元素铺满整个画幅（`x ∈ [3%, 97%]`），**严禁出现单调空旷的大块纯色留白边或内边框线**。

### 3. 封面原生 `21:9` (`1024×434`) 直出优先与零留白原则
* **优先调用支持原生 `21:9`（`2.35:1`，实测 `1024×434`）的渠道直出满版全景图**：通过 `scripts/gemini_web_bridge.py` 在 Prompt 中显式指定 `wide 21:9 panoramic full-bleed edge-to-edge composition with ZERO empty side margins`，可直接直出原生 `1024×434` 满版全景封（无需后期裁剪或外延拼接），推送时加 `--no-safe-crop` 保留 100% 满版；
* **若调用仅支持 `16:9` 的 API 生图**：必须要求构图水平满铺 `x ∈ [3%, 97%]`、纵向留出上下 `13%` 氛围延展并**从上下居中裁成 `2.35:1`**，**绝对严禁在左右两侧填充纯色/模糊条强行拉宽（会在草稿箱与订阅号卡片里显得边缘空洞极丑）**；
* **正文漫画插图规范（16:9）**：正文配图保留清爽 `#F3F5F7` / `#FBFBF7` 漫格纸面质感，配合实机操作截图形成对比，避免重色底抢夺橄榄手记正文白底阅读视觉。

### 4. 底色、构图与角色「去俗艳高定色板 + 一文一色一道具」铁律
* 🚫 **永久红线（严禁廉价配色）**：
  * **严禁**“红配紫/橙配紫”KTV/低端夜店霓虹双色聚光灯背景；
  * **严禁**“绿黄渐变/紫黄彩虹”等俗气多色胶囊色带；
  * **严禁**“粗黄奶油字配粗黑外描边”的廉价表情包标题字体与大块刺眼亮黄/亮紫满铺。
* ✅ **高定色板三原则（Apple Keynote / Linear / Teenage Engineering 极简工业审美）**：
  * **克制主底色**：统一选用高质感单色系摄影棚级底色（如 **苹果暖调银白画廊纸 `#F3F2EE`**、**黑曜石钛金暗调 `#0D0E12 ~ #171920`**、**极简冷灰工程纸 `#EEF1F5`** 或 **温润宣纸米白 `#F7F5EE`**）；
  * **高对比印刷级标题**：浅色底配纯正墨黑（`#111216`）无描边锐利大字 + 纯黑/深靛极简白字胶囊；深色底配纯白（`#F9FAFB`）无描边高反差标题 + 半透明毛玻璃微细银边胶囊；

* 🚨 **一文一色一道具（防连续同质化）**：每篇文章按主题在以下高定色板之间切换底色与核心道具，避免连续两篇同底色：
  * **硬件协作 / 桌面外设 / 办公效率类**：暖调银白画廊底（`#F3F2EE`）+ 墨黑标题 + 钴蓝交互引导弧线；火柴人戴 **银色无线头戴式降噪耳机** 操作极简铝金属键鼠/双屏；
  * **影视 / 视频剪辑类**：黑曜石钛金暗调底（`#0D0E12`）+ 纯白标题 + 香槟钛金高光；火柴人戴 **深灰贝雷帽** 手持香槟金剪刀，搭配目标商业软件图标 + VIP 锁标；
  * **合同 / PDF / 审单办公类**：瑞士印刷纸白（`#F6F7F9`）+ 墨绿/朱砂红单色印章点缀；火柴人戴 **半透明墨绿审单遮阳帽** 盖红印；

  * **装机清理 / 系统瘦身 / 跨端传输类**：冰川银白（`#F1F5F9`）+ 克制电光蓝（`#2563EB`）与极简警示红叉；火柴人推 **极简工业推车/磁吸传导线**；

## 五、 爆款封面 7 维出图与发前视觉终检清单

每次生成或选定公众号封面后，必须用原生看图能力逐一核验以下 **7 项视觉卡扣**（任一不达标直接重生成，严禁将就推送）：

1. **文字内容与零错字**：大字标题全中文、无乱码生造字、无冷门黑话（路人 0.5 秒能秒懂解决什么事）；
2. **主体元素与人物情绪**：白圆头火柴人完整未变成写实人类，暴漫表情（愤怒崩溃 vs 墨镜炫笑）对比强烈；
3. **色彩克制与去廉价感**：严禁红配紫聚光灯、彩虹渐变条与粗卡通黄字黑描边；必须具备苹果/Linear 级干净底色与单一克制点缀色；
4. **构图留白与居中安全框**：核心文字收敛在垂直 `18%~83%` 安全视窗内，左右火柴人完整踩在地面投影上、不贴边切脚；
5. **视觉风格一致性**：正文若采用「实机界面截图 + 暴漫火柴人」，色调协调、无违和水印；
6. **点击诱因明确**：一眼能看出「省了多少钱 / 释放了多少空间 / 解决了什么恶心事」；
7. **尺寸与文件体积**：`21:9` 横版全景（`1024×434` 等比），单图文件严格 `< 1MB`（防微信 `uploadimg` CDN 超限失败）。

## 六、 小绿书 / 贴图帖（`type=8 / newspic`）专属铁律（2026-11-23 实测踩坑固化）

常规图文是 `2.35:1` 横版封面，而小绿书贴图走完全不同的双重居中裁切机制，**严禁直接按常规竖版海报居中满铺**：

1. **标题物理硬上限 `<= 20` 字**：`type=8` 小绿书发表或列表展示时超过 20 个字会被微信直接截断成 `……`（例如 `11-23` 实测逾限即断尾），建议严格控制在 **`14 ~ 19` 字**。
2. **微信双重居中裁切数学规律（实测 100% 复现）**：
   - 上传 `3:4`（如 `765×1024`）作为首图创建 `newspic` 草稿时，微信服务端会先自动按 **`16:9`（`y ∈ [29%, 71%]`，如 `765×431`）** 生成缩略图 `thumb_url`；
   - 随后公众号后台「近期草稿」卡片用 **`203×270`（`3:4` 竖框 + `background-size: cover; background-position: 50% 50%`）** 展示该 `thumb_url`，导致**左右两端各被进一步裁掉 ~`29%`，仅露出最中心 `x ∈ [29%, 71%]`、`y ∈ [29%, 71%]`（约 `42% × 42%` 的面积）**！
3. **首图安全构图绝对红线（全幅画面 + 中心标题）**：
   - **主背景与视觉氛围必须全画幅 100% 铺满 `3:4`（`765×1024`）画布**，严禁把整张主体画面直接缩成居中 40% 小方块（否则点进小绿书全图或网页端保存为 `3:4` 后显得特别小气）；
   - 首图的核心文字标题与最关键主体焦点（如手部/透明手机轮廓），**收束在正中心安全框内（文字宽 `<= 276px`，即 `x ∈ [31%, 69%]`, `y ∈ [30%, 68%]`）**，其余部分由光影粒子、波形或深空场景自然向边缘延伸铺满。
4. **出图 + 推送双模拟核验（禁止凭感觉盲传）**：
   - 发前必须运行 `scripts/upload_newspic.py`（或自检脚本）先生成 `16:9 -> 203×270` 模拟裁切图并用 `read_file` 看清「不切字、不重影、主体完整」；
   - 推送草稿后脚本会自动回拉微信服务端真实的 `thumb_url` 并按 `203×270` 截取 `verified_thumb_card.jpg`，**必须再次 `read_file` 亲眼核验线上真实卡片**！\n
